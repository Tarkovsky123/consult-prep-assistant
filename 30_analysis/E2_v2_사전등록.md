# E2 v2 평가: 사전 등록 (2026-11-03, 시험 세트 정답표 고정 전·도구 실행 전)

> v1 결과(`30_analysis/결과_E2_측정.md`)와 오류 분석(`30_analysis/E2_오류분석_v1.md`)을 본 뒤에 쓴다. 그래서 기존 E2 30건은 **개발 세트**가 됐다. 제안서의 정확도는 아래 **시험 세트**에서만 잰다. 실행 뒤 이 규칙을 바꾸면 '변경 기록'에 사유와 바꾸기 전 결과를 함께 남긴다.

## 1. 세트

| 세트 | 사례 | 정답표 | 쓰임 |
|---|---|---|---|
| 개발 | E2 30건(대구·경북, '다른 사업' 1건 제외 29건 채점) | `E2_정답표_고정_20261103.csv`(f9b18928c1829de6) | v2를 고치는 데 쓴다. 여기서 낸 v2 점수는 '개발 세트 점수'로만 적는다 |
| 시험 A | **E2b 20건**: 대구·경북 밖 2025 협의완료 사례(`scripts/make_e2b_cases.py`, 시드 20261104, 유사도 0.7 이상 짝 417건 중 원문이 있는 앞 20건) | 사용자가 E2b 판정판에서 단 뒤 `E2b_정답표_고정_<날짜>.csv`로 고정 | 본 측정 |
| 시험 B | **합성 경계사례 11건**(S1~S11) | `합성_정답표_고정_20261103.csv`(c507dcb8297a1bf8) | 경계 규칙 점검(월→연 환산, 광역 합산, 지역 조건 등) |

- 표본을 뽑을 때 시제품 출력은 쓰지 않았다. 원문이 있는지만 봤다.
- 시험 세트에는 **v2 코드를 고정하기 전까지 어떤 방법(M0·M1·M2)도 돌리지 않는다.** 결과를 보고 v2를 고칠 여지를 없애려는 것이다.

## 2. 방법

| 방법 | 내용 | 코드 |
|---|---|---|
| M0 규칙 기준선 | v1 사전등록과 같다(LLM 없음) | `consult_prep.py --baseline`, v1 해시 |
| M1 시제품 v1 | LLM이 값을 추출하고, 유형 고르기와 협의제외는 키워드 규칙으로 한다 | `consult_prep.py` sha256 앞 16자리 `6b2df56df64eb168`(11/3 기록) |
| M2 시제품 v2 | M1 + **LLM 유형 선택**(키워드 상위 후보 유형 중 하나 또는 '해당없음'을 근거 구절과 함께 고름) + **LLM 협의제외 대조**(지침 Ⅱ.3 조항과 근거 구절) | 시험 세트 실행 직전에 해시를 아래 '변경 기록'에 적는다 |

- M2의 LLM 백엔드와 추론 수준은 M1과 같다(Codex CLI, medium). 바꾸면 기록한다.

## 3. 입력

- **E2b**: v1 사전등록 §1과 같다(사업명·기관·원문 세 칸).
- **합성**: `--name` = 사업안 전체, `--org` = 사업안에서 ':' 앞(예: '대구 군위군'). ':'가 없으면 비우고 기초지자체로 본다. `--text` = 사업안 전체.

## 4. 채점

v1 사전등록 §3·§4를 그대로 쓴다. 출력에서 라벨 칸으로 바꾸는 규칙, 분모, 보류 지표 세 가지(필요한 보류를 잡음·놓침·불필요한 보류)가 모두 같다.
- E2b에서 정답 '동일 사업'이 아니오인 사례는 뺀다. 뺀 수를 함께 적는다.
- 합성은 유형연번·대상·상한·협의제외·유형판정을 채점한다. 중복위반은 도구가 판단하지 않으므로 채점하지 않는다.
- **주 지표는 시험 A의 유형판정 정확도**다. 시험 A+B 합계와 세트별 값을 함께 적는다.
- M2가 M1보다 낫다고 쓰려면 같은 사례에서 두 방법의 결과를 짝지어 보여 준다(M2만 맞힘 / M1만 맞힘 건수). 표본이 작아 유의성 검정은 하지 않고 건수로만 쓴다.

## 5. 쓰지 않을 해석

- 시험 A는 20건, B는 11건이다. 비율은 이 표본에 대한 값으로만 쓴다.
- 합성 사례는 제안자가 만든 경계 사례라 실제 분포를 대표하지 않는다. 합계에 섞을 때 이 점을 함께 적는다.
- 정답표는 사람 1인(제안자)이 달았다.

## 6. 변경 기록

(v2 코드 해시, 시험 세트 정답표 해시, 실행 뒤 규칙 변경을 날짜와 함께 적는다)

- **11/3 시험 A 정답표 고정**: `E2b_정답표_고정_20261103.csv`, sha256 앞 16자리 `6c9bb4bb0c029b0d`. 20건 모두 '같은 사업'이라 채점 대상은 20건이다. 분포는 일반 15, 신속 4, 확인불가 1, 협의제외 0이고, 연번 해당없음이 14건이다.
- **11/3 정답을 먼저 본 사실(누출 위험)**: 정답표가 순서도와 맞는지 점검하느라, v2를 만들기 **전에** 시험 A 정답 20건을 봤다. 그래서 v2에는 개발 세트(E2 30건)나 `판정기준_E1_E2.md`에 근거가 있는 규칙만 넣는다. 규칙마다 근거가 된 개발 세트 사례를 코드 주석에 적는다.
  - 6번 '2자녀 이상 다자녀' 해석은 개발 세트 392에 이미 있었다. 판정기준 문서에는 이번에 적었다.
  - 시험 A에 협의제외가 0건, 확인불가가 1건뿐이라 이 세트의 보류 지표는 거의 정보가 없다. 보류 지표는 시험 B(합성)와 개발 세트의 값을 함께 보고한다.
- **11/3 M2 설계 변경(시험 세트 실행 전)**: §2의 '키워드 상위 후보 유형 중 하나'를 **'79개 유형 전체 중 하나'**로 바꿨다.
  - 이유: 개발 세트의 정답 유형 13개 중 4개가 키워드 순위 8위 밖이었다(474·417은 겹치는 낱말 없음, 396은 9위, 414는 8위).
  - LLM에는 유형 목록(연번·분야·사업명·대상·지원수준), 판정기준 ② 규칙, 판정기준 §2 협의제외 목록을 준다. 대상·상한 대조는 v1 규칙 그대로다.
- **11/3 v1 경로 회귀 확인**: `consult_prep.py`에 `--v2`를 넣고, 기관이 빈 입력(합성)을 처리하도록 고쳤다. 고친 코드를 `--v2` 없이 개발 세트에 다시 돌려 저장된 M0·M1 판정과 비교했고, 60건이 모두 같았다. 그래서 시험 세트의 M0·M1은 고친 코드로 돌린다.
