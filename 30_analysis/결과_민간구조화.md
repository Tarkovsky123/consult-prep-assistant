## 사람 라벨 대비 정확도 (11/2, 라벨 40건, `data/processed/eval_private_codex.md`)

- **기준선**: 복지로 기존 태그(생애주기·가구상황만 있음)
- **원 채점**: 라벨 칸에 적힌 문자 그대로 비교
- **정규화**: 표기 차이만 맞춤
  - '미상' = 빈 목록
  - 오타 수정: 융지→융자, 바우처,이용권→바우처·이용권
  - 소득 칸에 여러 값을 적은 라벨은 모델 값이 그 안에 있으면 일치

| 항목 | 모델(원 채점) | 모델(정규화) | 기존 태그(정규화) |
|---|---:|---:|---:|
| 생애주기 | 25% | **72%** | 55% |
| 가구상황 | 40% | 45% | 35% |
| 소득 자격 | 65% | **85%** | 태그 없음 |
| 중위소득 % | 100% | 100% | 태그 없음 |
| 지역 요건 | 90% | **90%** | 태그 없음 |
| 지원 형태 | 80% | **82%** | 태그 없음 |

**가구상황 45%는 그대로 믿기 어렵다.**
- 라벨 40건 중 가구상황 칸만 23건이 빈칸이다. 다른 항목은 모르면 '미상'이라고 적었다.
- 엇갈린 사례 다수는 라벨 칸이 비어 있는데 모델이 값을 넣은 경우다. 예: 탈북대학생 기숙사 → 모델 '다문화·탈북민'.
- 그래서 남은 불일치 50건을 `data/labels/private_adjudication.xlsx`로 사람이 다시 판정한다. 판정 뒤 `adjudicate.py score`로 다시 잰다.

**모델 쪽 오류로 보이는 유형**(판정 전 관찰)
- 학년·나이 범위를 생애주기 하나로만 매핑한다. 예: 초·중·고 → 아동만.
- 원문에 근거가 약한 '장애인' 가구상황을 추가한다.
- 소득 언급이 애매하면 '기타소득기준'으로 채운다. 라벨은 '미상'이었다.
